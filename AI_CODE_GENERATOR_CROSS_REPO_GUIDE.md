## 📋 Requirements for Cross-Repo Compatibility

### 1. **Consistent Directory Naming Convention**
```
LAYER-XXX LayerName/          ✅ CORRECT (space separator)
LAYER-XXX_LayerName/          ❌ WRONG (underscore separator)
```

**Action Taken**: Renamed directories in professional_excellence:
- `LAYER-001_Alert_Logic` → `LAYER-001 Alert Logic`
- `LAYER-002_Email_Templates` → `LAYER-002 Email Templates`

### 2. **Feature-Level YAML Structure**

File: `FEATURE_REQUIREMENTS_INDEX.yaml` (or `FEATURE-XXX-XXX_feature_name.yaml`)

Required fields:
```yaml
metadata:
  requirement_id: "FEATURE-XXX-XXX"     # Required!
  requirement_name: "Feature Name"      # Required!
  version: "1.0.0"
  status: "Active"
  owner: "Your Name"
  priority: "SHOULD HAVE"
  target_date: "2025-XX-XX"

layers:
  - layer_id: "LAYER-001"               # ID only (no name suffix)
    name: "Layer Name"                  # Name separate
    requirement_file: "LAYER-001_layer_name.yaml"  # Points to layer YAML
    responsibility: "What this layer does"
```

### 3. **Layer-Level YAML Structure**

File: `LAYER-XXX_layer_name.yaml` in each layer directory

Required sections:
```yaml
metadata:
  requirement_id: LAYER-XXX
  requirement_name: Layer Name         # Required!
  requirement_type: Layer
  parent_feature: FEATURE-XXX-XXX
  status: active

description: |
  What this layer does...

testing_requirements:
  test_pyramid:
    enforce_pyramid_ratio: true
    unit_to_integration_ratio: 2.0
  
  unit_tests:
    required: true
    minimum_count: 10
    coverage_threshold: 0.90
    expected_test_methods:
      - test_method_1
      - test_method_2
  
  integration_tests:
    required: true
    minimum_count: 5
    coverage_threshold: 0.85

acceptance_criteria:
  - criterion_id: AC-001
    criterion: "What needs to be built"
    status: active
    priority: critical
    required_tests:
      - test_method_1
    implementation_method: ClassName.method_name
    traceability:
      feature_requirement: REQ-XXX-XXX

traceability:
  requirement_to_test_mapping:
    AC-001:
      acceptance_criterion: "What needs to be built"
      implementation_method: ClassName.method_name
      unit_tests:
        - test_method_1
      integration_tests: []
```

### 4. **Directory Structure**

```
FEATURE-XXX-XXX_Feature_Name/
├── FEATURE_REQUIREMENTS_INDEX.yaml          # Feature-level spec
├── LAYER-001 Layer Name/
│   ├── LAYER-001_layer_name.yaml           # Layer-level spec ✅
│   ├── src/
│   │   └── implementation.py               # Generated by AI
│   ├── tests/
│   │   ├── test_unit.py                    # Generated by AI
│   │   └── test_integration.py             # Generated by AI
│   └── Requirements Verification/

│       ├── test_pyramid_report_*.yaml      # Generated by AI

├── LAYER-002 Layer Name/
│   └── (same structure)
└── src/
    └── feature_integration.py              # Generated by AI
```

## 🎯 Standardization Checklist

To make any repo compatible with the AI Code Generator:

- [ ] Rename layer directories to use **spaces** instead of underscores
- [ ] Create/update `FEATURE_REQUIREMENTS_INDEX.yaml` with `requirement_id` and `requirement_name` in `metadata`
- [ ] Create `LAYER-XXX_layer_name.yaml` files in each layer directory
- [ ] Include all required sections:
  - [ ] `metadata` with `requirement_name`
  - [ ] `description`
  - [ ] `testing_requirements` with test pyramid
  - [ ] `acceptance_criteria` with traceability
  - [ ] `traceability.requirement_to_test_mapping`
- [ ] Update feature YAML `layers` section to point to correct `requirement_file`

## 🎓 Key Lessons Learned

1. **Consistency is Critical**: The AI Code Generator expects very specific naming and structure
2. **No Modifications Needed**: The generator works across repos without code changes
3. **Standardize Once**: Set up the structure correctly once, then it "just works"
4. **Layer-Level Specs**: Each layer needs its own executable YAML specification
5. **Traceability Required**: AC-to-test mapping is essential for verification
